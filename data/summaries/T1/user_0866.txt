GitLab on hosted hardware works great. I maintain two different instances. One of them automatically updates itself, and it just works. I think they will migrate the systems which they host VCSes. Since they may need to make changes in the code to suit them, abandoning the legal stuff makes using, modifying and contributing back stuff easier. Li-Ion batteries lose the ability to provide energy at low temperatures, pretty fast. If the battery is aged, the effect becomes much more pronounced. When using an IDE, memory consumption can be tolerated. Indexers, analyzers, open files, sometimes other tools which run with the IDE. However, to spend 800Mb to change a single file is too much. Atom is not a complete IDE as VSCode or Eclipse by any means. Yes Atom has IDE packages and capabilities are started to be rolled in, but it's too young. God knows what will be the memory usage of Atom when it grows to a complete IDE with project-wide knowledge. Also, having enough resources is never a good excuse for an application to use massive amounts of memory. IIRC uCode updates are volatile. You re-install them to CPU on every boot. OS actually does this for you.
