You could use a reverse proxy.  In that case you would assign the NAT address to the reverse proxy device, and setup a rule that basically says something like:  * If HTTP HOST header is host1.yourcompany.com then forward all requests to 192.168.1.50 * If HTTP HOST header is host2.yourcompany.com then forward all requests to 192.168.1.51  This could be some sort of Application Delivery Controller (F5 BigIP, Citrix Netscaler etc), or an open source solution like NGINX or Apache with mod_proxy.  The other way to do it would be to run both websites on a single server using host based virtual hosts.  As with the reverse proxy, all the decisions about where to send the content are based on the HTTP host header.  [Here's an example of how to do it with Apache](https://www.liberiangeek.net/2014/09/run-multiple-websites-single-ubuntu-server-using-apache2/).  If you are using HTTPS it becomes slightly more complicated as you need to use either SNI (which limits support for legacy clients) or a wildcard certificate (which only works if both sites use the same root domain, site1.company.com and site2.company.com would both work with a single *.company.com wildcard, but site1.company1.com and site1.company2.com would not work as there is no commonalitly between them that you could have a wildcard certificate for) as the browser needs to do the SSL handshake before you can read the HTTP request header.
FTP is another protocol that is a bit like this.  Unless you want to open a large swathe of ports (i.e. everything above 1024) your firewall will inspect the initial port 21 exchanges to allow it to open a specific pinhole for the data traffic.  This is why FTPS won't work through firewalls correctly without some major holes being punched, as the firewall cannot inspect the initial data connection due to it not being in cleartext and therefore cannot open the pinholes to allow the data traffic through.

You go to a domain registrar and enter the domain name you want.  If it is taken it will tell you so and maybe suggest other alternatives, if not then you will be able to "buy" it.  Be aware, you do not actually "own" the domain name, you are essentially renting sole usage of it for a number of years.  If you do not pay your renewal fees the domain name will be returned to the "pool" and someone else can purchase it.  Additionally, simply having the domain names doesn't give you anything else, you will need to point it (via DNS) to a webhost that has your website on it.  Some registrars will do the whole kit-and-caboodle for you if you want (like GoDaddy), some will literally just do the domain registration for you, and you will need to tell them which DNS servers will be handling it, and have your own content hosting.
